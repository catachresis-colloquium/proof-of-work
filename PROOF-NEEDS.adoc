=== Invariant register (I1–I7) — status of the seam obligations

`+src/abi/.../Invariants.idr+` cross-references these IDs; this is the
authoritative status table. `PROVEN` = machine-checked proof in the
seam; `ASSUMED` = a stated assumption, not checked (for example a cryptographic hardness axiom, intentionally
unprovable); `PROVEN-WITH-AXIOMS` = checked, resting on a named axiom; `OPEN` = stated as an erased obligation the Rust does not
yet establish.

|===
|ID |Property |Status
|I1 |Verification soundness — a positive verdict implies a real
`+VerifiedSolution+` certificate (adjacency + SMT entailment) |`OPEN` —
Rust does not return the witness; certificate type defined, refinement
obligation open

|I2 |Mock verifier no weaker than the Z3 path (no false wins in no-Z3
builds) |`PROVEN` (2026-05-21) — `+verify_level_solution+` now
returns a tri-valued
`+VerificationVerdict { Verified \| Rejected \| CannotVerify }+`; the
no-Z3 mock returns `+CannotVerify+` unconditionally, so "`mock accepts`"

*NonDecreasing half* remains `OPEN` Rust-side: the schema does not carry a

`+sha256CollisionResistant+`, which states that `+sha256+` is *injective*
on all strings. That is an idealisation, not collision resistance: real
SHA-256 has a fixed-size output and so has collisions (pigeonhole), and
collision resistance only says they are infeasible to find. The Idris2
theory stays consistent because `+Digest+` wraps an unbounded `+String+`,
but the result is about an ideal hash, not the shipped one. Until it is
restated or admitted under `+TRUSTED-BASE-REDUCTION-POLICY+`, it is
unrecorded proof debt (there is no `+docs/proof-debt.md+`), so it is not

rather than a bare `OPEN` postulate. Promotion to a discharged theorem
would require either property-testing against the Rust serde
implementation or a Creusot (Pearlite) and Verus proof of the encoder/decoder pair

=== Verifiers

Assigned per
https://github.com/hyperpolymath/standards/blob/main/3-practice/PROOF-POLICY.adoc[PROOF-POLICY]:

* *Idris2* for the ABI seam (`+src/abi/+`). It is in place, and
  `+abi-verify.yml+` builds it.
* *Creusot*, with contracts in *Pearlite*, and *Verus*, both by default,
  for the first-party Rust side (§1.2): I1 (`+verify_level_solution+`,
  `+verify_formula+`), I4 (puzzle generation), the Rust half of I5, and the
  serde round trip of I7. No Rust contract or Verus code exists yet, so
  each of these stays `OPEN`.
* *SPARK* is for Ada code. Earlier text proposed SPARK for these Rust
  obligations; that rested on a withdrawn reading of the policy (see the
  note at the top of `+RUST-SPARK-STANCE.adoc+`).

The game's theme is cryptographic proof-of-work, so formal proofs that
verification is sound would fit it well. Most remaining work is Rust-side:
I1 and I4 still need API or implementation changes before their Idris2
statements can be inhabited.

=== Trusted base

Idris2 accepts a declaration with no definition, even with totality
required, so each of these acts as a postulate. Five such declarations in
the seam are statements rather than abstract functions:

[cols="2,1,3",options="header"]
|===
|Declaration |Invariant |True as stated?

|`+Invariants.packLevelsSolvable : (lvls : List Level) -> All Solvable lvls+`
|I4
|True, but it says nothing about the levels. `+Solvable lvl+` never
mentions `+lvl+`, so one solved board satisfies it for every level. I4
needs `+Solvable+` to tie the solution to the level's own board and goal.

|`+Invariants.progressionMonotone : (ds : List Difficulty) -> NonDecreasing ds+`
|I5
|No. Its own doc comment says so: `+[2,1]+` is not non-decreasing.

|`+Foreign.acceptedImpliesVerified+`
|I1
|No. It gives a `+VerifiedSolution+` for any board, given only
`+VerifyAccepted = VerifyAccepted+`.

|`+Invariants.sha256CollisionResistant+`
|I6
|Consistent, because `+sha256+` is abstract (the identity would satisfy
it). False of real SHA-256 (see the I6 row above).

|`+Invariants.serdeRoundTripCorrect+`
|I7
|Satisfiable: `+serialise+` and `+deserialise+` are abstract, so some pair
of functions makes it true.
|===

All five are erased (quantity `0`). Erased `Void` can be derived from
`+progressionMonotone+` (apply it to `+[2,1]+`) and from
`+acceptedImpliesVerified+` (apply it to the empty board), so the seam's
theory is inconsistent as a whole. Both derivations were checked with
Idris2 0.8.0 on 2026-11-17, in a scratch module that was not committed.
None of the results marked `PROVEN` uses them: `placePreservesWF`,
`mockNoStrongerThanZ3`, `decNonDecreasing` and `builtinPackMonotone` were
checked for this on 2026-11-17. A future proof must not use them either.
The three `OPEN` obligations would be better stated as type definitions
(the proposition to be proved) than as declarations that assert it.

CI now requires totality (`+opts = "--total"+` in the `.ipkg`) and refuses
holes and escape hatches. It cannot detect a declaration with no
definition, so this table is the record of them.

None of the five carries an `+-- AXIOM:+` or `+// TRUSTED:+` marker, and
there is no `+docs/proof-debt.md+`. Under
`+TRUSTED-BASE-REDUCTION-POLICY.adoc+` each of I6 and I7 must become one of
these:

* a *budgeted* trust (I7: property-test serde over the loader's levels,
  with the refutation budget written down);
* a *necessary axiom* (I6 qualifies only once it is restated as an
  idealisation and named as one; injectivity is false of SHA-256);
* a recorded debt.

Choosing which is the owner's call.
